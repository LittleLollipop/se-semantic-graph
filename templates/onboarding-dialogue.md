# 对话驱动模板（阶段一/二/三）

> 本文件是「对话驱动工作流」的提问脚手架。每个阶段按顺序向用户提问，
> **不要自己假设答案**；用户回答后录入语义节点并展示确认。

---

## 阶段一：画像对话（→ persona 节点）

开场（必须主动问，不猜）：

> 在动手之前，先花几分钟对齐这个项目的用户画像和需求。
> 这决定了后面所有设计——如果我猜错了方向，写出来的代码就不是你要的东西。

问题清单（按顺序，全部问完再录节点）：

1. **目标用户**：这个游戏/产品主要给谁玩/用？（年龄层、人群特征、设备平台）
2. **核心场景**：用户在什么场景下使用它？（碎片时间/沉浸/聚会/通勤…）
3. **痛点/动机**：用户为什么选它而不是同类？（现有方案缺什么？）
4. **"爽"时刻**：玩家最享受的一个瞬间是什么？（通关/高分/意外效果/社交炫耀…）
5. **"崩溃"时刻**：什么会让用户想卸载？（太难/太单调/卡顿/不公平…）
6. **平台与分发**：目标平台？（Steam/手机/网页…）单机还是联机？免费还是付费？

录入：

```bash
add --id persona_<标识> --label "<画像名>" --type persona \
    --summary "<谁在用 · 场景 · 痛点 · 爽/崩溃时刻>" --source "<用户确认>"
```

完成条件：**用户明确认可画像描述**，展示后确认。

---

## 阶段二：需求对话（→ requirement 节点）

基于已确认画像，逐条问：

> 基于这个画像，我们把玩法拆成需求。每条你给个优先级：M=必须 W=想要 N=不做。

1. 核心玩法循环是什么？（一句话描述玩家反复做的事）
2. 列出 3-8 条具体功能需求，逐条确认 M/W/N
3. 非功能需求：性能要求？平台兼容？发布渠道？
4. 范围边界：明确**不做**什么（防止镀金）

录入：

```bash
add --id req_<编号> --label "<需求名>" --type requirement \
    --summary "<功能/非功能 · M/W/N · 验收要点>" --source "需求 R-<编号>"
connect --from persona_<id> --to req_<编号> --kind drives
```

完成条件：**需求清单展示给用户，用户确认无增删**。

---

## 阶段三：架构评审（→ architecture/module/runtime_logic 节点）

基于已确认需求，产出设计给用户看（图或结构化文字），**不直接写码**：

1. **分层架构**：分几层？每层职责？（如 输入层/逻辑层/物理层/渲染层）
2. **模块划分**：每层几个模块？模块边界？模块间依赖方向？
3. **关键流程**：核心状态机/时序（如 游戏状态流转、主循环）
4. **数据流**：关键数据怎么流动？
5. **关键决策点**：列出需要用户拍板的技术选型/设计权衡

用户确认/修改后录入：

```bash
add --id arch_<层名> --label "<层名>" --type architecture --summary "<职责>"
add --id mod_<模块名> --label "<模块名>" --type module --summary "<边界>"
add --id logic_<标识> --label "<运行逻辑>" --type runtime_logic --summary "<状态机/路径>"
connect --from req_<id> --to arch_<层> --kind mapped_to
connect --from arch_<层> --to mod_<模块> --kind part_of
connect --from mod_<模块> --to logic_<逻辑> --kind implements
# 用户的设计决策/修改意见：
add --id decision_<标识> --label "决策：<主题>" --type decision --summary "<选了什么·权衡>"
connect --from decision_<id> --to <受影响的节点> --kind affects
```

完成条件：**用户对设计拍板**，修改意见已落为 decision 节点。
