# 需求维度清单（阶段二必查）

> **为什么有这个清单**：需求对话最容易犯的错是"只讨论了机制/逻辑就以为需求聊完了"。
> 每个项目类型都有**不可避免的需求维度**——不是每个维度都要做(M)，但每个维度都必须讨论过、
> 由用户明确 M/W/N。跳过讨论 = 开发到一半才发现"忘了问画面/音乐/操作方式"。
>
> 用法：阶段二开始时，按项目类型选取清单，**逐维度过一遍**。
> 每个维度问："这个维度你的想法是什么？M=必须 W=想要 N=本轮不做？"
> 用户答 N 也要记录（记 N 防返工：以后不会突然要求加）。

## 游戏项目

| 维度 | 要问的问题 | 典型答案示例 |
|---|---|---|
| 玩法机制 | 核心循环是什么？规则细节？ | 方块下落+物理堆叠+比楼高 |
| 画面视觉 | 美术风格？2D/3D？配色？ | 复古像素风 / 扁平简洁 / 低多边形 |
| 音乐音效 | 背景音乐风格？音效（放置/倒塌）？ | 轻快电子 / 无音乐 / 倒塌有冲击音效 |
| 操作方式 | 键鼠/手柄/触屏？按键布局？ | 键盘左右+旋转 / 支持手柄 |
| 手感 | 下落速度、操作响应、物理灵敏度 | 下落偏慢可微调 / 响应要跟手 |
| UI 与 UX | 主菜单/计分显示/结算界面？ | 简洁HUD / 有结算排行榜 |
| 性能 | 帧率目标？大量方块时卡顿？ | 60fps / 百块不卡 |
| 平台兼容 | 哪些平台？分辨率适配？ | Win/Mac / 窗口可缩放 |
| 发布分发 | 上架渠道？商店页素材？ | Steam / itch.io / 免费网页版 |
| 难度曲线 | 是否变难？成长系统？ | 时间压力递增 / 无难度变化 |
| 社交/排行 | 排行榜/分享/多人？ | 本地最高分 / 在线排行 |
| 存档 | 是否需要存档？ | 不需要 / 记录最高分 |

## 记法

```bash
# M（必须）：
add --id req_<维度>_<编号> --label "<需求名>" --type requirement \
    --summary "<内容> (M)" --source "<用户确认>"
# W（想要）/ N（不做）：同样记，summary 标 W 或 N
# N 尤其要记——防止以后被当作遗漏而返工
```

连边：`connect --from persona_<id> --to req_<编号> --kind drives`

## 清单的边界（勿滥用）

- 清单是**提问的脚手架**，不是需求本身——用户的话才是需求
- 维度答案可以是"没想好/你建议"——此时给出建议并请用户确认，而不是自作主张
- 用户明确说"这些不用问"的项目，可以收敛清单，但至少要确认一次"这些维度你都不关心？"
